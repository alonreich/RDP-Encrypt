SECTION 0 — TL;DR (READ THIS FIRST)
--------------------------------------------------------------------------------
RDP Vault is a self-contained single-file Avalonia UI application for Windows.
It stores RDP connection profiles (hosts, ports, usernames, optional passwords)
inside ONE encrypted file ("vault.rdpv"). It launches connections through
Windows' own mstsc.exe and removes the local traces that mstsc leaves behind
(registry history, Default.rdp, jump lists, recent items, and — when the user
opts in — UserAssist, prefetch and saved TERMSRV credentials). It supports
automatic re-locking, an optional (off by default) self-destruct, a printed
Recovery Code, Windows Hello quick unlock backed by the machine TPM, and
one-click desktop shortcuts.

If you are an AI agent asked to modify this project: read SECTIONS 4, 5, 6, 10
and 13 before touching anything. Do not weaken the crypto. Do not write any
secret to disk outside vault.rdpv. Do not reintroduce anything from the
"REGRESSIONS TO NEVER REINTRODUCE" list in SECTION 13.

SECTION 1 — WHO USES THIS AND WHY (PRODUCT CONTEXT)
--------------------------------------------------------------------------------
Target user : A person who connects via RDP to their own or company computers
              and wants:
              (a) no residue on the host PC they launch from — so a later user
                  of that PC cannot see which host was contacted;
              (b) one click to connect to a stored host:port, with credentials
                  optionally saved;
              (c) automatic re-lock after inactivity, WITHOUT killing running
                  RDP sessions;
              (d) on trusted PCs, unlock with Windows Hello instead of typing
                  the master password;
              (e) desktop shortcuts for frictionless connections;
              (f) a way back in if they forget the master password.

Usage model : Portable (run the exe from a USB stick next to its vault.rdpv) or
              installed to %LOCALAPPDATA%\RDPVault via the built-in installer.
              Single instance is enforced per Windows session via a named mutex
              plus a NamedPipe that forwards --launch requests.

--------------------------------------------------------------------------------
Language        : C# 12, nullable reference types ENABLED, implicit usings ON.
Platform        : .NET 9, TFM net9.0-windows10.0.19041.0 (WinRT projections for
                  the Windows Hello APIs).
UI framework    : Avalonia UI 11.1.3 (XAML + code-behind; the shared dialogs are
                  built in code — see Dialogs.cs).

  *** THIS IS NOT A NativeAOT BUILD. ***
  v1.0.0 of this document claimed "NativeAOT-compiled" and told agents to build
  with PublishAot. There has never been a PublishAot property in the csproj. The
  csproj now states PublishAot=false and PublishTrimmed=false explicitly,
  because ShellLink.cs uses COM interfaces a trimmer cannot see and WinRT plus
  the managed Argon2 are awkward under full AOT.

NuGet packages (exactly five):
  1. Isopoh.Cryptography.Argon2   — Argon2id KDF (managed).
  2-5. Avalonia, Avalonia.Desktop, Avalonia.Themes.Fluent, Avalonia.Fonts.Inter

  System.Security.Cryptography.ProtectedData (DPAPI was dropped from the design
  but the reference stayed behind).

Windows-only APIs used:
  - AES-GCM via System.Security.Cryptography.AesGcm
  - Windows.Security.Credentials.KeyCredentialManager (WinRT, Hello keys)
  - advapi32.dll: CredWriteW, CredDeleteW, CredEnumerateW, CredFree
  - Microsoft.Win32.Registry (mstsc history, UserAssist, file association,
    uninstall entry)
  - IShellLink / IPersistFile COM (ShellLink.cs) for .lnk creation
  - System.IO.Pipes + named mutex Local\RDPVault_SingleInstance
  - manage-bde (spawned) for the BitLocker status read-out

Build command (canonical):
  build.cmd                 clean, publish, then REPLACE the GitHub release
  build.cmd --no-publish    clean and publish only, touch no release
The single artifact is compiled\RDPVault.exe. build.cmd itself runs:
  dotnet publish RDPVault\RDPVault.csproj -c Release -r win-x64 ^
      -p:PublishSingleFile=true -p:SelfContained=true -o obj\SingleFile_final
Exit codes: 0 = built and published, 1 = build failed (release untouched),
2 = built fine but the release step stopped.
Dev machine needs: .NET 9 SDK, plus gh (signed in) to publish. Target machines
need Windows 10/11 only — the build is self-contained, so no runtime install is
required. See SECTION 14 for the release/distribution rules.

SECTION 4 — CRYPTOGRAPHY SPEC (EXACT PARAMETERS — DO NOT WEAKEN)
--------------------------------------------------------------------------------
KDF (password -> key):
  Argon2id (Isopoh Argon2Type.HybridAddressing == Argon2id;
  Argon2Version.Nineteen == v1.3).
  Salt      : 32 random bytes, base64 in the vault file. RE-SALTED on every
              password change.
  Memory    : 65536 KiB (64 MiB).   Iterations: 3.   Lanes/Threads: 4.
  Output    : 32 bytes, zeroed after use. The UTF-8 copy of the secret is also
              zeroed and the Argon2 instance disposed (v1.0.0 did neither).

  NOTE: v1.0.0's Models.cs actually defaulted to 262144 KiB / t=5 while this
  document claimed 64 MiB / t=3. 1.1.0 makes the code match the spec. Existing
  vaults carry their own Kdf block and keep using it, so old 256 MiB vaults
  still open — they simply stay slow until the password is changed.

Cipher: AES-256-GCM, 12-byte random nonce per seal, 16-byte tag appended.

Key hierarchy:
  masterPassword --Argon2id(Kdf)--> passwordKey --AES-GCM--> Wrap     (masterKey)
  RecoveryCode   --Argon2id(RecoverySalt)--> recoveryKey --AES-GCM--> Recovery
  TPM signature  --Argon2id(Kdf.Salt)--> tpmKey --AES-GCM--> Seals[i].TpmBlob
  payload JSON   --AES-GCM(masterKey)--> Data

RECOVERY CODE (new in 1.1.0 — the v1.0.0 "24-word paper key" did not exist):
  256 bits of entropy rendered as 52 Crockford-Base32 characters in 13 groups of
  4 (alphabet 0-9 A-Z minus I, L, O, U). Input is normalised — case, dashes and
  spaces ignored, I/l -> 1, O -> 0, U -> V — then fed to Argon2id as the secret.
  The code is displayed exactly once, at creation or when regenerated, and is
  NOT recoverable from the vault. It wraps the same masterKey, so it survives
  password changes.

Quick-unlock hardware binding (per PC):
  MachineId = first 8 bytes of SHA-256("{MachineName}|{UserDomain}|{UserName}").
  Hello proof = KeyCredential.RequestSignAsync over
      "RDPVault::QuickUnlock::v2::<MachineId>".
  The raw TPM signature feeds Argon2id to derive tpmKey. That only works if the
  signature is byte-reproducible, so enrollment signs TWICE and compares, and
  test-unseals the new seal before saving it. If the signature is randomised
  (PSS / ECDSA), enrollment refuses and says so instead of silently creating a
  seal that can never open.

Vault file format (vault.rdpv = UTF-8 JSON, minified). V=2:
{
  "V": 2,
  "Kdf":   { "Salt": "<b64>", "Mem": 65536, "Iter": 3, "Lanes": 4 },
  "Wrap":  { "Nonce": "<b64>", "Ct": "<b64 ct||tag>" },
  "Recovery": { "Nonce": "<b64>", "Ct": "<b64>" },   // absent in V1 vaults
  "RecoverySalt": "<b64>",
  "Seals": [ { "MachineId": "<16 hex>", "TpmBlob": "<nonce>:<ct>", "KeyId": "<64 hex>" } ],
  "Policy": { "SelfDestructEnabled": false, "MaxAttempts": 25,
              "WindowMinutes": 60, "ThrottleEnabled": true },
  "Fails":  { "Count": 0, "FirstFailUtc": "...", "LastFailUtc": "..." },
  "Data":  { "Nonce": "<b64>", "Ct": "<b64>" }
}
Policy and Fails are DELIBERATELY unencrypted: they must be readable while the
vault is locked, they contain no secrets, and keeping them inside vault.rdpv
means an attacker cannot reset the failure counter without touching the very
file they are attacking.

V=1 vaults load unchanged (missing Recovery / Policy / Fails default in) and are
rewritten as V=2 on the next save.

Payload (decrypted Data): { "Profiles": [...], "Settings": {...} }
RdpProfile: Id, Name, Host, Port, Username, Password, UseMultiMon, GatewayHost,
  FullScreen, Width, Height, AllowClipboard, AllowDrives, AllowPrinters,
  AllowSmartCards, AllowUnverifiedServer (new), Notes.
VaultSettings: LockMinutes(60), KillSessionsOnUsbRemoval(true), ForceMultiMon,
  DeepSweep(false), SweepScope(OwnHostsOnly), WarnIfDriveNotEncrypted(true).
  RequireFido2 was REMOVED — it was stored and shown but enforced nowhere.

Error messages: Wrap tag failure -> "Wrong password." Data tag failure or JSON
failure -> one sentence pointing at the .bak file.

Atomic save: write vaultPath + ".tmp", copy the current vault to ".bak", then
File.Replace. There is always one previous good copy on disk.

IMPORTANT: a password change re-salts the KDF AND wipes ALL seals (treated as a
possible compromise), so every PC must re-enroll Hello. Preserve this.

SECTION 5 — RUNTIME MECHANICS (END-TO-END FLOWS)
--------------------------------------------------------------------------------
5.1 STARTUP  (App.OnFrameworkInitializationCompleted — the ONE place that decides)
    --uninstall present                          -> UninstallWindow
    running from %LOCALAPPDATA%\RDPVault
      OR a vault.rdpv sits next to the exe       -> MainWindow
    otherwise                                    -> SetupWindow

5.2 FIRST RUN
    MainWindow shows a "no vault found" panel with a single "Create a new vault"
    button. That opens Dialogs.CreateVaultAsync (password + confirmation +
    10-character minimum + strength read-out), creates the vault, then forces the
    Recovery Code screen, which cannot be dismissed until acknowledged.
    Typing into the unlock box NEVER creates a vault.

5.3 UNLOCK (password)
    MainWindow.SubmitPasswordAsync -> Task.Run(SessionManager.UnlockWithPassword)
    -> cooldown check -> VaultCrypto.Open -> ClearFailures -> AfterUnlock().
    On failure: SecurityEnforcer.RecordFailure (see 5.9).

5.4 UNLOCK (Recovery Code)
    "I forgot my master password" -> Dialogs.AskRecoveryCodeAsync ->
    SessionManager.UnlockWithRecoveryCode -> VaultCrypto.OpenWithRecoveryCode.
    On success the user is told to set a new master password.

5.5 UNLOCK (Windows Hello)
    Attempted automatically 300 ms after the window loads when a seal exists for
    this MachineId, and on demand from the button.

    FOREGROUND HANDLING (issue #21). KeyCredentialManager has no interop for
    passing an owner HWND — unlike UserConsentVerifier — so its prompt is hosted
    unparented by CredentialUIBroker.exe / LogonUI.exe and routinely opened
    behind the app without focus. A fingerprint presented to the sensor at that
    point is discarded, forcing the user to click the dialog first.
    Every KeyCredentialManager call is therefore wrapped in
    SystemPromptFocus.Begin(), which:
      1. activates our own window so this process holds the foreground;
      2. calls AllowSetForegroundWindow(ASFW_ANY) so the broker may take it;
      3. runs a 120 ms watchdog that locates the broker's visible top-level
         window (by class "Credential Dialog Xaml Host", or by owning process)
         and keeps it topmost and focused via AttachThreadInput +
         SetForegroundWindow until the scope is disposed, then releases topmost.
    The watchdog only ever touches windows owned by the known broker processes.
    Whichever window may raise the prompt must call SystemPromptFocus.SetOwner
    with its own HWND first — MainWindow does this on Loaded and before each
    attempt, SettingsWindow before enrollment, and MainWindow takes ownership
    back when the Settings dialog closes.

5.6 CONNECT
    MainWindow.BtnConnect_Click -> RdpLauncher.Launch(profile):
     1. Touch() the idle timer.
     2. Write %TEMP%\rdpv_{Id}.rdp.
     3. If a password is saved: CredWriteW a GENERIC credential with
        CRED_PERSIST_SESSION for BOTH "TERMSRV/{Host}" and, when the port is not
        3389, "TERMSRV/{Host}:{Port}". The password never enters the .rdp file.
     4. Process.Start(System32\mstsc.exe, "<temprdp>").
     5. A background task waits for exit, deletes the temp .rdp, deletes every
        credential it wrote, runs TraceCleaner.Sweep(), raises SessionEnded.
        It does NOT read the .rdp back or modify the stored profile.
     6. The Process handle is kept in LiveSessions for KillAll and the exit prompt.

5.7 AUTO-RELOCK
    A 1 s DispatcherTimer (created and started ON THE UI THREAD) locks the vault
    once LockMinutes of inactivity have passed. Activity = unlock, connect,
    shortcut creation, opening or saving Settings and the profile editor, any
    pointer or key event inside the window, and pipe messages. Locking never
    closes running RDP windows. The header shows a live "locks in mm:ss".

5.8 LOCK / EXIT
    Lock(): zero masterKey, drop payload, raise Locked, optional KillAll, then
    DeepSweep() if the setting is on else Sweep(), then TraceCleaner.ForgetHosts()
    so host names are not retained in memory. Dispose() does the same.
    Closing the window while RDP sessions are open asks for confirmation first.

5.9 BRUTE-FORCE HANDLING
    Always on: after 5 failures inside the window, each further attempt is
    refused until an escalating delay (2, 4, 8 ... 60 s) has elapsed.
    Optional: self-destruct. OFF by default; cannot be armed until a Recovery
    Code exists; requires typing ERASE; attempts clamped to 5-500. When it fires,
    vault.rdpv, its .bak and its .tmp are overwritten with random bytes and
    deleted, and the UI says exactly what happened.

5.10 SINGLE INSTANCE + SHORTCUTS
    Mutex Local\RDPVault_SingleInstance. A second instance sends "SHOW" or
    "LAUNCH:<profileId>" over pipe RDPVault_Show and exits.
    Desktop shortcuts are real .lnk files targeting
    RDPVault.exe --launch <profileId>. The installer also registers .rdpvlink ->
    RDPVault.Link so shortcuts created by v1.0.0 finally work.

5.11 USB REMOVAL
    2 s poll of AppContext.BaseDirectory / Environment.ProcessPath. On loss:
    raise UsbRemoved, Lock (killing sessions per setting), DeepSweep, exit.

5.12 UNINSTALL
    UninstallWindow asks first: "keep my vault" (default — copies vault.rdpv and
    its .bak to Documents\RDP Vault Backups before anything is removed) or
    "erase my vault" (requires typing ERASE; overwrite-then-delete).
    --quiet always takes the KEEP path: a silent uninstall must never destroy
    user data.

SECTION 6 — TRACE CLEANING SPEC
--------------------------------------------------------------------------------
All in TraceCleaner.cs. Every step is TryRun-wrapped; cleanup must never crash
or block. Sweep() runs after each RDP window closes, on unlock, on lock and on
exit. DeepSweep() = Sweep() + credential wipe.

SweepScope.OwnHostsOnly (DEFAULT):
 1. HKCU\...\Terminal Server Client — delete MRU values whose DATA matches a
    vault host; inside "Default", delete values matching a vault host; inside
    "Servers", delete only subkeys matching a vault host.
 2. Documents\Default.rdp — deleted only if it references a vault host.
 3. Jump lists — *.automaticDestinations-ms deleted only if they contain both
    "mstsc" and a vault host.
 4. Recent items — only rdpv_* and names mentioning a vault host.
 5. %TEMP%\rdpv_*.rdp — always.
 6. UserAssist and Prefetch — NOT touched (they prove only that mstsc ran and
    are shared with the user's non-vault usage).
 7. DeepSweep credential wipe — only TERMSRV/* targets naming a vault host.

SweepScope.Everything (opt-in, spelled out in Settings): the v1.0.0 behaviour —
every MRU value, the whole Servers and Default subtrees, every mstsc jump list,
every *.rdp* in Recent, UserAssist ROT13 mstsc counters, MSTSC.EXE-*.pf, and
every TERMSRV/* credential.

DELIBERATELY NOT touched in either mode: Windows Event Logs, RDP server-side
logs, anything outside the current user's profile. Say so honestly in README.

SECTION 7 — GENERATED .RDP FILE (RdpLauncher.BuildRdpFile)
--------------------------------------------------------------------------------
UTF-8 (no BOM) at %TEMP%\rdpv_{Id}.rdp. Notable settings:
  screen mode id / desktopwidth / desktopheight / use multimon
  full address:s:<host> or <host>:<port> when port != 3389
  redirectclipboard / redirectprinters / redirectsmartcards <- profile toggles
  redirectdrives + drivestoredirect:s:*  ONLY when AllowDrives
  username:s:<username>   (password NEVER here)
  gatewayhostname / gatewayusagemethod / gatewayprofileusagemethod
  authentication level:i:2   <- REQUIRE server verification (default)
  authentication level:i:1   <- only when the profile opts into
                                AllowUnverifiedServer (warn, still not silent)
  enablecredsspsupport:i:1 - negotiate security layer:i:1
  prompt for credentials:i:0 - autoreconnection enabled:i:1 - pcb:s:

  v1.0.0 hard-coded "authentication level:i:0", which silences mstsc's server
  identity check completely. Never set 0 again.

Defaults are deny-by-default: drives, printers and smart cards off, clipboard on.

Session credential: CredWriteW Type=GENERIC, TargetName "TERMSRV/{Host}" and
"TERMSRV/{Host}:{Port}" when non-default, blob = UTF-16LE password,
Persist = CRED_PERSIST_SESSION, deleted on window close.

SECTION 8 — UI STRUCTURE & STATE MODEL
--------------------------------------------------------------------------------
Theme: dark. Bg #0E0E10, panel #121215/#141417, border #2E2E35, accent #005FB8,
ok #2FBF71, warn #E8A030, danger #B80000, text #EDEDED, dim #8A8A93. Keep new
controls consistent, including the code-built dialogs in Dialogs.cs.

MainWindow is the only persistent window and flips between:
  LockedPanel  : password box + Unlock, optional Windows Hello button,
                 "I forgot my master password", status and error lines.
                 When no vault exists it shows the first-run panel instead.
  MainPanel    : optional warning strip, profile cards (Connect / Shortcut /
                 Edit / Delete), live "locks in mm:ss", status line.

The status line reports real events (connecting, session closed, traces cleaned,
locked, USB removed, shortcut results). v1.0.0 hard-coded it to the untrue
string "Connected to Hardware TPM."

The warning strip tells the truth about state, e.g. "this vault has no Recovery
Code".

ProfileEditorWindow edits a CLONE and exposes ApplyTo(target), so Cancel really
cancels and editing never changes the profile's Id. It validates: name required,
host required and space-free, port 1-65535. The password field is masked with a
"Show password" toggle.

SettingsWindow: auto-lock (1-1440), change master password, create/replace
Recovery Code, Windows Hello on/off, sweep scope + deep sweep, force multi-mon,
BitLocker warning with a live status read-out, and the self-destruct box.

Dialogs.cs: ConfirmAsync (with optional type-to-confirm), MessageAsync,
CreateVaultAsync, ShowRecoveryCodeAsync, AskRecoveryCodeAsync,
ChangePasswordAsync.

XAML / WinRT gotchas (do not re-learn these):
  - CheckBox has NO TextWrapping -> wrap Content in a <TextBlock>.
  - KeyCredentialManager.OpenAsync (NOT RequestOpenAsync).
  - KeyCredential.RequestSignAsync (NOT SignAsync).
  - KeyCredential.RetrievePublicKey is SYNCHRONOUS.
  - IBuffer lives in Windows.Storage.Streams;
    CryptographicPublicKeyBlobType in Windows.Security.Cryptography.Core.
  - Argon2id enum member is Argon2Type.HybridAddressing.
  - AesGcm ctor requires an explicit tag size (16).
  - Avalonia DispatcherTimer has UI-thread affinity — never create or Start one
    from inside Task.Run.
  - Never call KeyCredentialManager from a background thread, and never without
    a SystemPromptFocus.Begin() scope — the prompt lands behind the app.
  - Avalonia HWND: TopLevel.TryGetPlatformHandle()?.Handle.

SECTION 9 — SECURITY MODEL SUMMARY
--------------------------------------------------------------------------------
Protects against:
  - Forensic discovery of RDP targets on the host PC after use (per SECTION 6,
    within the chosen scope).
  - Theft of the drive: AES-256-GCM + Argon2id(64 MiB). BitLocker is recommended
    and its status is reported honestly.
  - Offline brute force of the file: memory-hard KDF.
  - In-app brute force: escalating delay, counter stored inside the vault file.
  - Credential leakage at rest: RDP passwords never touch the .rdp file; session
    credentials are Persist=SESSION and deleted on window close.
  - Server impersonation: authentication level 2 by default.

Assumes / does NOT protect against (be honest in any fork):
  - An attacker with the user's unlocked Windows session on a Hello-enrolled PC.
  - Memory forensics on a running unlocked instance. .NET strings holding
    profile passwords cannot be reliably zeroed; only the master key is.
  - Windows Event Log / EDR telemetry of mstsc execution.
  - Deleted-file carving. The vault shredder is best effort; SSD wear levelling
    and copy-on-write filesystems can defeat overwrite-in-place.
  - Anyone who copies vault.rdpv before attacking it — the in-vault failure
    counter and self-destruct only govern this app's own attempts.

SECTION 10 — EXTENSION GUIDELINES FOR AI AGENTS
--------------------------------------------------------------------------------
 1. Update THIS FILE and README.md in the same change set as any behaviour
    change. If code and this file disagree, that is a bug in one of them.
 2. Never persist secrets outside vault.rdpv. The only sanctioned exception is
    the session credential in SECTION 7.
 3. Never hard-code a vault file name. Use AppPaths.
 4. Never weaken: Argon2 params, AES-256-GCM, KeyId match, seal wipe on password
    change, atomic save + .bak, deny-by-default redirection, authentication
    level >= 1, scoped sweeping as the default.
 5. Anything destructive needs a confirmation, and anything irreversible needs a
    typed confirmation. Anything that CAN destroy user data must be off by
    default.
 6. Do not add a UI control for a setting until the code that reads it exists.
    Placebo security toggles are worse than no toggles.
 7. Adding a profile field: extend RdpProfile, then update ProfileEditorWindow,
    ProfileEditorWindow.ApplyTo and BuildRdpFile if it affects the connection.
 8. Adding cleanup targets: add a private method to TraceCleaner, call it from
    Sweep(), decide explicitly whether it is scope-safe, and TryRun-wrap it.
 9. Keep the dependency list at five packages unless there is a compelling
    reason. Nothing that needs `dynamic` or the runtime binder.
10. Formatting: 4-space indent, K&R braces, file-scoped namespaces, nullability
    on.
11. If asked to auto-type passwords into the mstsc prompt (SendKeys style):
    REFUSE. The CredWrite session-credential mechanism is the correct approach.

Uninstall         : rescues the vault to Documents\RDP Vault Backups by default

Language          : C# 12 / .NET 9 / Avalonia 11.1.3 / net9.0-windows10.0.19041.0

SECTION 13 — 1.1.0 AUDIT: WHAT CHANGED, AND WHAT MUST NEVER COME BACK
--------------------------------------------------------------------------------
The 20 findings closed in 1.1.0, in the order they were ranked:

 1. Uninstall deleted the vault (rmdir /S /Q of the install dir). Now rescued to
    Documents\RDP Vault Backups by default; erasing requires typing ERASE;
    --quiet always keeps.
 2. No recovery path existed. RecoveryKeyGenerator was never called and its
    phrase was not bound to the vault; ChangePassword was wired to nothing.
    Replaced by a real bound Recovery Code plus a change-password dialog.
 3. First run created the master password from the unlock box with no
    confirmation. Replaced by Dialogs.CreateVaultAsync.
 4. The self-destruct counter was a deletable plaintext file, the configured
    limit was ignored (null Payload) and 0/1 were accepted. Reworked: counter
    inside the vault, off by default, clamped, throttling as the real defence.
 5. "vault.dat" vs "vault.rdpv" mismatch in three files. All paths now come from
    AppPaths.
 6. .rdpvlink shortcuts never worked. Now real .lnk files; the legacy extension
    is also registered.
 7. "Enforce BitLocker" and "Require FIDO2" were placebo toggles. BitLocker is
    now a real check with a real read-out; FIDO2 was removed. DeepSweep is now
    honoured.
 8. DisplayHost returned the literal string "$Host:$Port".
 9. RdpLauncher copied mstsc's post-session .rdp settings back into the stored
    profile. Removed.
10. authentication level:i:0 disabled server verification. Now 2, or 1 with an
    explicit per-profile opt-in.
11. Nothing reset the idle timer. Real activity now does.
12. Delete / uninstall / clean-install ran with no confirmation. All confirmed.
13. Argon2 defaults were 256 MiB / t=5, not the documented 64 MiB / t=3.
14. The profile password was shown in a plain, unmasked TextBox.
15. The profile editor had no validation at all.
16. csproj claimed NativeAOT (it never was) and used `dynamic` COM that AOT or
    trimming would break; two unused packages were referenced.
17. The status line was hard-coded to "Connected to Hardware TPM."; UsbRemoved
    and SessionEnded were never subscribed.
18. (a) DispatcherTimer was started from a background thread; (b) credentials
    were written only for TERMSRV/{host}, so non-3389 profiles never found them;
    (c) TPM signature determinism was assumed. All three addressed.
19. Argon2 instances undisposed, password bytes unzeroed, the master key leaked
    on a JSON failure, ChangePassword dereferenced possibly-null state.
20. TraceCleaner erased the user's entire mstsc history unconditionally. Now
    scoped to vault hosts by default.
21. (reported after the audit) The Windows Hello / TPM prompt opened in the
    background without focus, so a fingerprint presented at that moment was
    ignored and the user had to click the dialog first. Fixed by
    SystemPromptFocus — see SECTION 5.5.

REGRESSIONS TO NEVER REINTRODUCE
  - Any code path that deletes vault.rdpv without an explicit typed confirmation.
  - Any hard-coded vault file name outside AppPaths.
  - "authentication level:i:0".
  - A settings control with no enforcing code behind it.
  - Reading mstsc's temp .rdp back into the stored profile.
  - Creating or starting a DispatcherTimer off the UI thread.
  - `dynamic` / WScript.Shell for shortcut creation.
  - Storing the brute-force counter outside the vault file.
  - Calling KeyCredentialManager without a SystemPromptFocus scope.

SECTION 14 — RELEASE & DISTRIBUTION POLICY
--------------------------------------------------------------------------------
THERE IS EXACTLY ONE DOWNLOAD. Not one per version — one, full stop.

  https://github.com/alonreich/RDP-Encrypt/releases/latest/download/RDPVault.exe

That URL is the only link README.md may offer. It is version-agnostic, so the
README never needs editing when a new build ships, and it can never point at a
stale installer.

The invariant is enforced by build.cmd, not by discipline:
  * compiled\ is wiped and rebuilt, then :VALIDATE_COMPILED_OUTPUT fails the
    build if anything other than RDPVault.exe survives in it.
  * :PUBLISH_RELEASE deletes EVERY existing release and its tag (--cleanup-tag)
    before creating the new one, so only one release ever exists.
  * The new release is tagged vYYYY.MM.DD and carries the one exe.
  * The upload is verified two ways before the script reports success: the
    asset's SHA-256 must equal the certutil hash of the file just built, and the
    release must carry exactly one asset. Either check failing exits with code 2
    ("built fine, release not updated") rather than leaving a bad download live.

The same exe is the installer, the portable app and the uninstaller. Never add a
second asset, a separate setup wrapper, a portable zip or a versioned filename —
each one creates a second thing a user can download and get wrong.

If a build fails, the previous release is left completely untouched. A broken
build must never take the working download offline.
